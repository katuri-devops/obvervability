GET /policies/{policy_id} in policy-api.yaml describes, following

PROJECT_RULES.md section 14. The coverage check reads the policy the same

way.


1. Add redis to app/policy-service/requirements.txt, at the version in

  PROJECT_RULES.md section 5.

2. Add the variable REDIS_URL from section 8 to the policy-service entry

  in app/compose.yaml. Change nothing else in that file.

3. Read the policy from Redis under the key policy:{policy_id}. If it is

  there, use it, and answer GET /policies/{policy_id} with

  "source": "cache". If not, read the database, store the policy in

  Redis for 60 seconds, and answer with "source": "database". Store only

  policies that exist.

4. Wait at most 1 second for Redis, and try each command once. If Redis

  is not available, log a WARNING and read the database, as if the

  policy were not in Redis, without trying to store it. Redis is never a

  reason to answer 503.

5. Keep everything else as it is: the answers, the coverage rules, the

  error answers and the checks of the request.
